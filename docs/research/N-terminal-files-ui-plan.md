### 文件和拷贝是一件事（产品负责人 11-28：“拷贝还是不好用”“文件这块和拷贝感觉很像”）

- 现状（代码）：画面走 QUIC 数据报（我们自己的节奏器发）；文件（`StreamKind::File`）、剪贴板（`StreamKind::Clipboard`）、浏览（`StreamKind::Browse`）
  各走一条 QUIC 流。**逻辑上分开，但同一条连接、同一条路、同一个拥塞控制**；代码里没有给这些流设优先级（没有 `set_priority`），
  也没有按画面给文件限速。所以大文件或大剪贴板在传时会挤占画面：排队变长 → 码率控制看到延迟上升 → 画面码率降、变糊或卡。F4 就是修这个。
- 做法照 Windows：资源管理器的拖放、复制粘贴底下是同一个复制引擎。我们也只有**一个传输引擎**：
  - 文件管理、剪贴板里的文件粘贴、拖放都走它；
  - 共用断点续传、冲突（替换、跳过、比较）、进度窗口（暂停、取消）、给画面让路的限速。
- 剪贴板：复制时只通知“复制了什么”，对方按粘贴时才取，交给传输引擎。小的文字和图片照旧立即同步。
  已有分支 `worktree-agent-aa350fb390850f11b`（剪贴板按需取，4 个提交，落后 dev 226 个）：审过以后照思路在现在的 dev 上重做，不直接合。
  读过它的 `docs/research/clipboard-lazy.md`（11-28）：思路对（RDP 的做法：复制只发“有什么”，来取才传；系统的延迟提供数据），
  但系统那一层大半没在真机上跑过（它自己列了 9 条待验证）。重做分三步，每步能单独交付：
  - **C1（跨平台，Linux 上能全测）**：协议 `Held`/`Want`/`Unavailable`/`Same`；复制时只发 `Held`；在远程窗口按粘贴键时扣住按键、
    传完对方确认再按（带进度、能取消）；文件走 F1 的传输引擎、限速走 F4；被控端 → 控制端在工具条上给“取对方复制的内容”。
    这一步就修掉“一复制画面就卡”。
  - **C2（Windows、macOS 延迟提供）**：Windows `WM_RENDERFORMAT`（文字、图片），macOS `NSPasteboardItem` 数据提供者；
    右键菜单“粘贴”也能取到。用 `[win]`、`[mac]` 和产品负责人真机按旧分支 3.0.1 的清单过。
  - **C3（Windows 文件像资源管理器）**：OLE `IDataObject` + `CFSTR_FILEDESCRIPTORW`/`CFSTR_FILECONTENTS` + `IStream`，
    资源管理器自己显示复制进度、能取消、自己处理冲突；协议加“按文件、按范围取”。macOS 的 Finder 先实测再选 `public.file-url` 或文件承诺。
- 验收：Mac ↔ Windows ↔ Linux 三个方向文字、图片、文件都能复制粘贴；粘贴大文件时弹进度、能取消；粘贴期间画面冻结 ≤ 1 s。

## 标准（产品负责人 11-28 定，每步按它验收）

- **文件**：像 Windows 资源管理器那样顺手。具体到：
  - 本机和远端之间 Ctrl+C / Ctrl+V 能复制文件；拖放两个方向都行（包括从远程画面拖到本机桌面）；
  - 多选（Shift、Ctrl、框选），右键菜单（打开、复制、剪切、粘贴、删除、重命名 F2、新建文件夹、属性）；
  - 键盘操作（方向键、回车、退格回上级、按字母跳到文件）；地址栏和面包屑；按列排序；图标和缩略图；
  - 进度窗口：速度、剩余时间、暂停、继续、取消；
  - 冲突对话框：替换、跳过、比较两边的大小和时间，“对所有文件这样做”；
  - 删除进回收站；重命名、删除、移动能撤销（Ctrl+Z）。
- **终端**：到 iTerm2 这一档（或 Ghostty、WezTerm、Warp 同类）。具体到：
  - 配色方案（内置几套好看的，跟随亮暗）、字体（等宽字体、连字、Nerd Font 图标、CJK 对齐）、最小对比度；
  - 标签和分屏；搜索（支持正则）；智能选择和复制、点链接打开；
  - shell 集成（命令标记、命令成功失败、跳到上一条命令，OSC 133）；命令结束和响铃的通知；
  - 平滑滚动、GPU 绘制不卡；断线回来接着用。
- **界面**：看国外同类产品怎么布局，细节照最好的做：
  - 加载中、连接中、断网、重连、对方离线、权限不够这些状态都要有、要说清原因和办法；
  - 文件传输的进度和结果、终端的配色和字体、整体的字体、间距、图标、亮暗主题；
  - 手机和 PC 都按这个标准。

## 产品负责人定的（11-28）

- **观看模式以后加**：只看画面、不能操作（同行都有）；和终端的“只读观看”一起设计，Agent 用户常常只想看进度，手机上误触也不会出事。
- **不做帧率设置**：我们的帧率跟着内容走（变了马上编、马上发，最高到编码器上限），用户不用选；少一个选项，界面也少一个会被误解的地方。
