# 做 Agent 的手、眼和闸门，不做大脑

“用手机聊天让自己电脑上的 AI 干活”在 2026 年已经被验证，而且正被模型厂商和平台免费或打包送出：ChatGPT 桌面端的 Work/Codex（含后台操作电脑）对 Free 用户开放（2026-07-09）【已核实】([OpenAI](https://openai.com/index/chatgpt-for-your-most-ambitious-work/))，Claude Dispatch 随 Pro 以上订阅提供【已核实】([Claude Blog](https://claude.com/blog/dispatch-and-computer-use))，腾讯 WorkBuddy 的手机远控“不消耗 Token”（2026-10-28）【未核实】([凤凰网](https://tech.ifeng.com/c/8xaeluxtnMt))；国内远控同行也已上线，向日葵 16.5（2026-06-16）把远控做成全功能 MCP 并内置 OrayClaw【已核实】([向日葵](https://sunlogin.oray.com/news/53723.html))，ToDesk AI 约 2026-05 上线【已读二手】([搜狐](https://www.sohu.com/a/1041452981_458778))。所以 PeerDesk 做“又一个 Agent”赢不了，能赢的是这些方案共同的短板：电脑必须醒着且 App 开着（Dispatch 帮助页原文）【已核实】([Claude Help](https://support.claude.com/en/articles/13947068-assign-tasks-to-claude-from-anywhere-in-cowork))，远程访问靠用户自己拼 Tailscale，以致 OpenClaw 实例大量暴露在公网【未核实】([Bitsight](https://www.bitsight.com/blog/openclaw-ai-security-risks-exposed-instances))，看不到实时画面，只能连一台，绑死一家模型。这些正是 PeerDesk 已有的无人值守、P2P 打洞和中继、低延迟画面与接管。技术上业内共识是“工具优先、屏幕兜底”：同一批任务混合路线成功率 75.12%，高于纯截图 GUI 的 70.65% 和纯 MCP 的 53.23%（MCPWorld，2025-06，Claude 3.7 Sonnet）【已核实】([MCPWorld](https://arxiv.org/pdf/2506.07672))；按 2026-11 官方价推算，“找文件并发出去”走结构化工具约 $0.02 一次（Sonnet 5.5），走截图约 $0.3–0.7，贵 10–30 倍（推断）。能力有天花板：熟练用户要一小时以上的真实任务，最强模型严格通过率只有约 20%（OSWorld 2.0，Opus 4.8 20.6%）【已核实】([OSWorld 2.0](https://osworld-v2.xlang.ai/))，人必须能随时看、随时接管。安全上没有厂商能靠模型挡住提示注入，Anthropic 原话是“No browser agent is immune to prompt injection”【已核实】([Anthropic](https://www.anthropic.com/research/prompt-injection-defenses))，权限分级、手机确认、审计和隔离必须做进架构。建议第一步：只对本人账户设备开放的“找文件、发文件”工具型 Agent，同一套工具同时以 MCP 服务和 CLI 开放，模型默认自带 Key（BYOK）直连，工具做不到的事明确说明并一键切到实时画面由人接管，任务成功率、单次成本和注入攻击成功率进端到端门槛。

## 一、同行在做什么：国内远控已让远端电脑听聊天干活，欧美同行只给技术员当助手

**结论**：截至 2026-11，把“远程桌面”和“聊天驱动的 Agent”合在一起、面向普通用户上线的只有中国厂商（向日葵、ToDesk、华为）。欧美远控厂商的 AI 全部面向 IT 支持和 MSP，MCP 只开放管理面。模型厂商和操作系统都在做“手机派活、电脑执行”，但没有一家提供远程画面通道，而且都要求电脑醒着、App 开着。下表列出能从手机或聊天让远端电脑干活的主要方案。

### 欧美远控厂商：AI 只服务“技术员修别人的电脑”，改动一律要批准

TeamViewer 投入最大，也是唯一公布采用数据的一家。会话内排障 Agent Tia 于 2025-11-18 发布，2026-09 的 Tia Troubleshooting 能从诊断一路做到执行修复，但原文写明“actions that make changes require approval and are logged for visibility and auditing”【已核实】([TeamViewer 2026-09](https://www.teamviewer.com/en/insights/teamviewer-september-2026-news/))。2026-09-24 发布的 MCP 建在 REST API 之上，能管租户、查设备健康、重启或连接设备、取会话日志，但明说“In-session features are handled by Tia”，即**不让外部 Agent 直接操作远端桌面**【已核实】([TeamViewer MCP](https://www.teamviewer.com/en/insights/introducing-teamviewer-model-context-protocol-integration/))。其他欧美同行形态相同：GoTo 的 Resolution Agent（2026-05-19）诊断后由技术员一键批准执行【已核实】([GoTo](https://www.goto.com/blog/2026-resolve-rescue-ai-features))；NinjaOne 的 Katana AI 和 MCP（2026-10-13）沿用基于角色的访问控制【已核实】([NinjaOne](https://www.ninjaone.com/press/katana-ai-and-mcp/))；Kaseya 2026-11-17 发布三个早期访问的第一方 MCP，自有的 Agent Center 要到 2027 年，原则是“AI finds and suggests and people make the calls”【已核实】([Kaseya](https://www.kaseya.com/press-release/kaseya-expands-its-agentic-it-management-platform-with-first-party-mcp-servers-pre-built-skills-and-a-unified-cyber-resilience-portal/))；BeyondTrust 的 MCP Gateway 只读、只在美国区提供【已核实】([BeyondTrust](https://docs.beyondtrust.com/rs/reference/mcp-gateway))；N-able（2026-04 公开预览）和 ConnectWise 的同类功能【未核实】([N-able](https://www.n-able.com/press/press-releases/n-able-makes-uem-ai-native-with-mcp-server-launch))。Splashtop 的 AI 只用在编解码器和补丁摘要上，没有会话助手也没有 MCP【已核实】([Splashtop](https://www.splashtop.com/press/unified-platform-for-modern-it-announcement))。AnyDesk、Parsec、Chrome 远程桌面、Apple 屏幕共享、Quick Assist 没找到 AI 功能，但这只是“没搜到”，没有逐一翻发布说明【未核实】。

TeamViewer 的数据揭示了一条产品规律：用 AI 的客户 12 个月从 6,921 涨到 62,953（2025-09 → 2026-09），会话结束自动生成的 Session Insights 累计 **4,003,701 份**，而需要人主动对话或批准的 Tia 上线约 10 个月只有 **32,068 次交互**【已核实，自报】([TeamViewer](https://www.teamviewer.com/cn/insights/teamviewer-ai-adoption-grows-ninefold-in-twelve-months/))。两者单位不同，但相差两个数量级：零门槛、不改习惯的功能普及得快，Agent 执行普及得慢。AI 也还没带动收入：2026 年三季度营收 1.845 亿欧元，按固定汇率同比 −2.2%，ARR 7.369 亿欧元（−0.6%），全年营收指引下调到 −2% 至 −1%【未核实，Quartr 的 AI 摘要】([Quartr](https://quartr.com/events/teamviewer-ag-tmv-q3-2026_3s1TBnKs))；两份笔记对中小企业业务的说法相反（一说下滑，一说企稳），要以公司原文为准。计费上，TeamViewer 用按月发放、续费日清零的 AI 积分：每份总结 1 积分，Tia 会话按消息数 1–4 积分，新写一个脚本 5 积分，**没有公布每积分单价**【已核实】([TeamViewer KB](https://www.teamviewer.com/en-us/global/support/knowledge-base/teamviewer-remote/teamviewer-ai/ai-credit-based-payment-model/))；2026-07 的俄文版知识库写着另一套规则，说明半年内改过【未核实】([俄文 KB](https://www.teamviewer.com/ru/global/support/knowledge-base/teamviewer-remote/licenses/licenses-and-features/ai-credit-based-payment-model/))。

### 国内：向日葵、ToDesk、华为已经能“对远端电脑说话”

向日葵走得最远，资料也最透明。16.5 版（2026-06-16）的“全功能 MCP”覆盖设备管理、命令调用、模拟键鼠、识屏执行和远程传文件，**已装向日葵的被控设备不用更新就能直接支持**，内置的 OrayClaw 执行过程全程可视、可随时接管【已核实】([向日葵 16.5](https://sunlogin.oray.com/news/53723.html))。MCP 活动页列出 `control_command()`，用于“在无桌面环境下执行命令”，支持 stdio 和 HTTP 两种模式，有免费试用但没写价格【已核实】([向日葵 MCP](https://activity.sunlogin.oray.com/mcp))；2026-08-07 的说明称任何支持 MCP 的模型都能调用，危险操作可设成人工确认，有审计日志和隐私屏【已核实】([向日葵 AI 远控](https://sunlogin.oray.com/news/56887.html))。MCP 首发大约在 2026-03-06【未核实】([CSDN](https://www.csdn.net/article/2026-03-06/158740180))，2026-07 成为首个接入腾讯 WorkBuddy 的远控方案【未核实】([同花顺转载](https://stock.10jqka.com.cn/20260717/c678249388.shtml))。

ToDesk AI 约 2026-05 上线（搜狐 2026-06-25 称“正式上线一个月”，凤凰网写 2026-05-27）。它靠“看屏幕”模拟键鼠，“一个账号，就能调动你名下所有设备”，手机可用语音或文字下任务，执行画面实时回传、可以接管，支付和输密码交给用户【已读二手，偏软文】([搜狐](https://www.sohu.com/a/1041452981_458778))；删除和修改前要用户确认，新用户送 2,100 积分、每天登录送 1,000【已读二手】([快科技](https://news.mydrivers.com/1/1128/1128230.htm))；另一来源称注册送 5,000 积分、基于开源 OpenClaw 深度定制【未核实，与前者冲突】([ai-bot.cn](https://ai-bot.cn/sites/77198.html))。ToDesk 的 Agent 是在云端看画面操作还是在被控端本地执行，报道互相矛盾（有报道称“运算都在云端”）【未核实】([凤凰网](https://tech.ifeng.com/c/8tbcCD2OFyY))，需要实测。华为走系统路线：HarmonyOS 7 的“跨端找文件”让用户在手机上描述需求，合盖待机的同账号电脑检索并回传文件【已读二手，IT之家 2026-09-07】([IT之家](https://www.ithome.com/0/999/340.htm))；小艺 Work 正式版 2026-11-06 发布，可从鸿蒙手机、平板远程给电脑（含 Windows）下任务、看进度、收结果【已读二手】([腾讯新闻](https://news.qq.com/rain/a/20261106A0DP1200))。腾讯 WorkBuddy 在 Agent App 里补了手机远控，一台电脑同一时间只允许一部手机，报道只提到 macOS【未核实】([凤凰网](https://tech.ifeng.com/c/8xaeluxtnMt))。网易 UU 远程没有官方 AI，但开发者用它的终端在手机上处理家里电脑上 Claude Code 的确认提示，不需要串流画面【未核实】([CSDN](https://damodev.csdn.net/6ac07d8f05257b0857147bd7.html))。

### 模型厂商和操作系统：都在做“手机派活”，都要求电脑醒着

Anthropic 是能力、产品、协议三条线都齐的一家。API 侧的 computer use 已升级为免 beta 头的 `computer_toolset_20260801`，含 17 个成员工具；它是**客户端工具**，截图和动作都在开发者自己的环境里采集和执行，“Claude never connects directly to the environment”【已核实】([Claude computer use 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool.md))，这意味着 PeerDesk 可以用自家执行层接任意一家的 computer use 模型。产品侧，Dispatch 让手机和桌面共用一个会话，“Claude will reach for the most precise tool first, starting with connectors”，屏幕操作是兜底且更慢，支持 macOS 和 Windows【已核实】([Claude Blog](https://claude.com/blog/dispatch-and-computer-use))；帮助中心写明它是部分 Pro、Max、Ultra 计划的有限 beta，**已不再接受新用户**，“your computer needs to be awake and the Claude Desktop app open”，Linux 版没有 computer use，不能开多个线程【已核实】([Claude Help](https://support.claude.com/en/articles/13947068-assign-tasks-to-claude-from-anywhere-in-cowork))；有安全研究者逆向后称远程指令除 Claude 账号会话外没有额外认证【未核实】([Pluto Security](https://pluto.security/blog/inside-claude-cowork-how-anthropics-autonomous-agent-actually-works/))。

OpenAI 的 Codex 桌面端 computer use（2026-04-16）用“its own cursor”操作应用，多个 Agent 可以并行而不干扰用户，初期只支持 macOS【已核实】([OpenAI](https://openai.com/index/codex-for-almost-everything/))；2026-05 起可从手机下任务，在 Mac 锁屏且屏幕关闭时操作应用，但不能操作终端和系统管理员提示【已读二手】([MacRumors](https://www.macrumors.com/2026/05/22/codex-use-mac-apps-when-locked/))；2026-07-09 Codex 并入 ChatGPT 桌面端，Chat、Work、Codex “在所有计划可用，包括 Free”，Codex 周用户超过 500 万【已核实，自报】([OpenAI](https://openai.com/index/chatgpt-for-your-most-ambitious-work/))，但官方没说清手机发起的任务是否在用户自己的电脑上执行。Google 2026-06-24 把 computer use 做成 Gemini 3.5 Flash 的内置工具，覆盖浏览器、手机和桌面，附两项可选企业护栏（敏感动作要用户确认、检测到间接注入自动停任务）【已核实】([Google](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-computer-use-gemini-3-5-flash/))；2026-11-19 的 Gemini Mac 客户端在“isolated background window”里执行，聊天里实时预览，不占用户的主屏和光标【已读二手】([9to5Google](https://9to5google.com/2026/11/19/gemini-mac-computer-use/))。

微软把 Agent 做进了操作系统。Windows Agent Workspace 给每个 Agent **独立账户和独立 Windows 会话**，比 Windows Sandbox 轻，可申请 6 个已知文件夹并按 Agent 设“始终允许、每次询问、从不”，默认关闭、只有管理员能开，Agent 的动作可与用户区分并写入防篡改审计日志，目前仍是 Insider 私有预览【已核实】([Microsoft Support](https://support.microsoft.com/en-us/windows/ai/ai-features/experimental-agentic-features))。Build 2026（2026-06-02）发布执行容器 MXC 早期预览，并用 MXC 在容器里跑 Windows 原生的 OpenClaw，同时宣布给 Agent 用的云 PC Windows 365 for Agents 在 Agent 365 内 GA【已核实】([Microsoft Source](https://news.microsoft.com/source/asia/features/build-2026-furthering-windows-as-the-trusted-platform-for-development/))；但 Microsoft Learn 的介绍页写的是“公开预览、仅限美国”【未核实，与前者冲突】([Microsoft Learn](https://learn.microsoft.com/en-us/windows-365/agents/introduction-windows-365-for-agents))。Apple 在 WWDC26 走 App Intents 结构化路线，公开材料里**没有 macOS 通用 computer use，也没有系统级 MCP**，MCP 只出现在 Xcode 里【已核实】([Apple](https://developer.apple.com/videos/play/wwdc2026/102/))。其余玩家：Meta 约以 20 亿美元收购 Manus（2025-12-29），Manus 2026-03-16 推出 My Computer，在用户的 Mac 和 Windows 上执行命令、读写文件，每条命令要用户批准，电脑须开着且 App 在运行【未核实】([CNBC](https://www.cnbc.com/2026/03/18/metas-manus-launches-desktop-app-to-bring-its-ai-agent-onto-personal-devices.html))；Perplexity Personal Computer（2026-04-16）把一台 Mac mini 变成 7×24 常驻 Agent，首发只给 $200/月的 Max 用户，heise 却报 $167/月，可能是年付折算【未核实，冲突】([MacRumors](https://www.macrumors.com/2026/04/16/perplexity-personal-computer-for-mac/))、([heise](https://heise.de/-11209925))；Anthropic 2026-02-25 收购 Vercept，其远程操作 MacBook 的产品 Vy 随即关停【未核实】([Anthropic](https://anthropic.com/news/acquires-vercept))。

这些产品有两个共同趋势（推断）：Agent 不再抢用户的鼠标（Codex 自有光标、Gemini 隔离窗口、Windows 独立会话），而“常驻、无人值守”是前提（Dispatch 要求唤醒，Perplexity 推荐 Mac mini 常开）。两者都是远程桌面的老本行：PeerDesk 可以让 Agent 跑在独立的虚拟显示或会话里，用户照常用电脑，同时通过 PeerDesk 画面旁观、一键接管。

### 开源和 MCP 生态：OpenClaw 是事实标准，“远控内置 MCP”还只是小项目

OpenClaw 约 39.5 万星、8.3 万 fork，MIT 许可，口号是“The AI that really does things”，可通过 WhatsApp、Telegram、iMessage、Slack 等 20 多个聊天渠道指挥，有 macOS、iOS、Android、Windows、Linux 原生节点，但页面没有明确宣称通用 GUI computer use【已核实】([GitHub openclaw](https://github.com/openclaw/openclaw))。它在中国引发“养龙虾”热，腾讯云上部署 OpenClaw 的用户截至 2026-03-06 已超过 10 万【未核实】([财联社](https://www.cls.cn/detail/2309484))。其他成熟开源件：Browser Use 12.2 万星、MIT【已核实】([GitHub](https://github.com/browser-use/browser-use))；微软 UFO（MIT）的 UFO² 用 Windows 无障碍接口 UIA、Win32、COM 加视觉混合控制，UFO³ Galaxy 把任务拆成有向无环图、按能力分给多台设备【已核实】([GitHub UFO](https://github.com/microsoft/UFO))。“远程桌面加 MCP”目前只有小项目：QuickDesk（自身代码 MIT，远程组件基于 BSD-3 的 Chromium Remoting，Qt/C++ 加 Rust 写的 MCP 桥，传输用 WebRTC）内置 MCP，被控端还有提供文件和 shell 的 skill host，601 星，README 一处写“40+ MCP tools”、另一处写 20+【已核实，工具数自相矛盾】([GitHub QuickDesk](https://github.com/barry-ran/QuickDesk))；另有一个同名仓库约 277 星【未核实】([GitHub](https://github.com/acardozzo/quickdesk))。RustDesk 官方没有 AI，但社区提案 #16246（2026-09-16）要做一个默认关闭、只绑回环地址、控制端本地的 MCP，67 个工具覆盖会话、截图、输入、文件、剪贴板、终端和 TCP 隧道，被控端不用改；维护者回复“Go ahead”并要求先提完整 PR，2026-11-12 有用户指向 PR #16470【已核实】([RustDesk #16246](https://github.com/rustdesk/rustdesk/discussions/16246))。PeerDesk 的窗口期有限。

MCP 已是事实标准。2025-12-09 MCP 捐给 Linux 基金会下的 Agentic AI Foundation，当时 Python 和 TypeScript SDK **每月下载超过 9,700 万次**、活跃公开 server 超过 1 万个【已核实】([MCP Blog](https://blog.modelcontextprotocol.io/posts/2025-12-09-mcp-joins-agentic-ai-foundation/))；第三方称官方 Registry 2026-09-24 有 35,491 个 server，Glama 2026-10-11 索引了 97,619 个【低质量】。当前规范 2026-07-28 版去掉了协议级会话和 `initialize` 握手，变成**无状态**；新增必须实现的 `server/discover`；tasks 移出核心成为官方扩展；Streamable HTTP 去掉了 SSE 断点续传，流断了请求就丢、客户端必须重发；新增 `Mcp-Method`、`Mcp-Name` 头方便网关路由；动态客户端注册（DCR）弃用，改用客户端 ID 元数据文档（CIMD）【已核实】([MCP Changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog))。这正适合“每台被控电脑暴露一个 MCP 端点、经 PeerDesk 的 P2P 或中继到达”的架构，但长任务必须走 tasks 扩展，不能指望长连接（推断）。

许可证方面，OpenClaw、Browser Use、UFO、QuickDesk 是 MIT（QuickDesk 的远程组件为 BSD-3），微软 Mage-VL-Cowork 模型是 Apache-2.0，Fara 系列模型是 MIT，都可以借用，但要写进 `THIRD_PARTY_NOTICES.md`【已核实】。智谱 Open-AutoGLM 据评测模型 MIT、代码 Apache-2.0【未核实】。**Open Interpreter 据记忆自 2024 年起改为 AGPL-3.0【未核实】，确认前不能引入**；UI-TARS-desktop、Desktop Commander MCP、Windows-MCP 的许可证因调研环境拦截 GitHub 没能核对，借用前必须到仓库确认。

## 二、技术路线：工具优先、屏幕兜底，混合路线成功率最高、步数最少

**结论**：截图加视觉模型的 GUI 路线什么软件都能操作，但慢、贵、长任务不可靠；MCP、命令、文件这类结构化工具快且便宜，但覆盖不全；“能用工具就用，否则退回屏幕”的混合路线在三组独立研究里成功率都最高、步数最少，也是一线产品的实际做法。Claude Dispatch 先用连接器、屏幕兜底【已核实】([Claude Blog](https://claude.com/blog/dispatch-and-computer-use))；微软 MagenticLite（2026-05-21）把浏览器任务交给截图循环的 Fara1.5，文件和代码任务由编排模型直接调 bash、edit、search、open 工具【已核实】([MagenticLite](https://microsoft.com/en-us/research/blog/magenticlite-magenticbrain-fara1-5-an-agentic-experience-optimized-for-small-models))。

| 路线 | 代表产品 | 成功率证据 | 时间 | 每任务成本 | 主要失败和风险 |
|---|---|---|---|---|---|
| 纯 GUI（截图 + 视觉模型） | ToDesk AI、OrayClaw 识屏、豆包虚拟桌面 | MCPWorld 70.65%；0–5 步 90.41%，10 步以上 35.56% | OSWorld 短任务每题 74–141 秒；长任务 15–33 分钟 | 短任务 $0.01–0.71；长任务 $2.9–10 | 推理不足、超时；屏幕上所有文字都是注入面 |
| 纯工具（MCP、命令、文件） | 向日葵 `control_command`、华为跨端找文件 | MCPWorld 53.23%，失败中 48.42% 是工具覆盖不足 | 推断 5–20 秒 | 推断 $0.001–0.02 | 覆盖不全；工具多了模型反而不用 |
| 混合（工具优先、GUI 兜底，UIA 加视觉融合） | Claude Dispatch、微软 UFO²、MagenticLite | MCPWorld 75.12%，10 步以上 51.11%；UFO² 用 o1 时 16.3% → 24.5%，步数 16.0 → 6.6 | 介于两者之间 | 介于两者之间 | 仍以推理不足为主（占失败 85.41%） |

表中 GUI 路线的时间和成本来自 cua-speedrun（2026-09-30，单篇论文、单次运行、不含环境托管费，分数是带部分得分的平均分）【已核实】([cua-speedrun](https://arxiv.org/html/2609.40284))；工具路线的时间和成本是推断，没有找到同一任务两条路线的实测对比。

MCPWorld（2025-06，201 题、10 个应用，Claude 3.7 Sonnet）是最直接的对照：短任务（0–5 步）GUI 和混合都是 90.41%，纯 MCP 只有 63.01%；10 步以上混合 51.11%，明显高于 GUI 的 35.56%。失败原因上，纯 GUI 72.88% 是推理不足、18.64% 是超时，纯 MCP 48.42% 是工具覆盖不足，混合把覆盖不足降到 4.17%【已核实】([MCPWorld](https://arxiv.org/pdf/2506.07672))。微软 UFO²（2025-04，Windows）给出两条可以直接照搬的结论：同样 27 个办公任务，加入 API 后 o1 成功率从 16.3% 升到 24.5%、平均步数从 16.0 降到 6.6；控件检测上只用 UIA 得 25.3%，只用视觉解析得 20.8%，两者融合得 27.9%，所以 Windows 上应同时取 UIA 控件信息和截图，而不是二选一【已核实】([UFO2](https://arxiv.org/html/2504.14603v2))。另有两条证据提醒“工具多不等于会用”：OSWorld-MCP 发现即使给了工具，模型的工具调用率也只有 33%–36%【未核实，版本间数字有出入】([OSWorld-MCP](https://arxiv.org/html/2510.24563v2))；调研笔记还转述 MCPWorld 作者推测“MCP 工具描述过长会干扰中等长度任务”，但这与笔记列出的 5–10 步分档数字（混合 74.70% 高于 GUI 72.29%）对不上，需回原文核对。即便如此，PeerDesk 的工具集也应当少而精、描述短。需要说明的是，这些对照用的都是 2025 年的模型，2026 年前沿模型在同一批日常任务上的三路线对照还没人做过。

基准分数是厂商宣传的主战场，口径很乱，不宜直接引用。OSWorld 原论文的人类成功率是 **72.36%**【已核实】([OSWorld](http://osworld-v1.xlang.ai/))。2026 年 OSWorld-Verified 的“第一名”各说各话：Steel.dev 汇总榜列 Qwen3.8-Max 86.1%（阿里自报）、Claude Fable 5 85.0%，并警告各行的框架、步数上限、工具权限不同，不能直接比较【已核实（汇总页），数字为厂商自报】([Steel.dev](https://leaderboard.steel.dev/leaderboards/osworld/))；Yutori 称 claude-fable-5 86.0%，Presenc.ai 称官方榜第一是 90.19%【未核实，互相矛盾】([Presenc.ai](https://presenc.ai/research/osworld-computer-use-leaderboard-2026))；官方 Verified 榜由前端脚本加载，调研时没读到。更能说明真实能力的是 OSWorld 2.0（2026-06-26 上线）：108 个长流程任务，人类中位用时约 1.6 小时，Opus 4.7 每题平均 318 次工具调用；500 步上限下 Claude Opus 4.8 **严格通过率 20.6%**、部分得分 54.8%，GPT-5.5 约 14%【已核实】([OSWorld 2.0](https://osworld-v2.xlang.ai/))。厂商的口径冲突要明说：Anthropic 报 Opus 5.5 在“OSWorld 2.1”上 81.8%，标注 partial 但没解释【已核实，自报】([Anthropic](https://www.anthropic.com/news/claude-opus-5-5))；Simular 称 Sai 以 73% 登顶 OSWorld 2.0，同一份 README 又说 Agent S4 严格通过率 21.3%【已核实，自报】([Agent S](https://raw.githubusercontent.com/simular-ai/Agent-S/main/README.md))；cua-speedrun 在 OSWorld2 的 52 题子集上测得 Opus 5（low）52.1%，也是带部分得分的平均分【已核实】([cua-speedrun](https://arxiv.org/html/2609.40284))。合理的读法是：高分都是部分得分口径，一小时级真实任务的严格成功率仍在 20% 左右（推断）。

时间几乎全花在模型推理上。cua-speedrun 用 1920×1080 截图在 OSWorld 50 题上测得 Claude Opus 5（low）每题 85.9 秒、14.04 轮，Sonnet 5（high）140.8 秒、20.24 轮，折合**每轮约 6–7 秒**（推断）；开放权重的 Kimi K3（max）443.7 秒、GLM-5V Turbo 752.4 秒；长任务 OSWorld2 上 Opus 5（low）每题 1,385.7 秒（约 23 分钟）、146.5 轮【已核实】([cua-speedrun](https://arxiv.org/html/2609.40284))。同一论文把环境 I/O 从标准 OSWorld 的点击中位 2,515 毫秒压到 27.6 毫秒后，模型时间约占 95%【已核实】。OSWorld-Human（2025-06）发现规划和反思占任务时间的 75%–94%，一个调行距的任务 Agent 用了 12 分钟、人不到 30 秒，Agent 的步数是人类必需步数的 1.4–2.7 倍（v1 版本数字），而且越往后每步越慢【已核实】([OSWorld-Human](https://arxiv.org/html/2506.16042v1))。对 PeerDesk 的含义（推断）：自家毫秒级的采集和输入注入不是瓶颈，要优化的是轮数（批量动作、换成工具调用）和每轮 token（截图缩小、只留最近几张）；手机上走 GUI 路线用户要等分钟级，必须实时显示进度并允许接管，PeerDesk 的远程画面本身就是现成的“看 Agent 干活”窗口。

以“找今天桌面上的 PDF，把合同发出去”为例，最便宜可靠的路径是系统索引加少量结构化工具（推断）：Windows 上通过 OLE DB 用 SQL 语法查 Windows Search 索引【已核实】([Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/search/-search-sql-windowssearch-entry))，macOS 上用 Spotlight 的 `NSMetadataQuery`（官方页面没加载出来，属性细节未核实）([Apple](https://developer.apple.com/documentation/foundation/nsmetadataquery))，Linux 或索引没覆盖时直接遍历目录；模型先从文件名判断，拿不准时读 PDF 前一两页的文字而不是截图；发回本人就走 PeerDesk 已有的文件传输，发邮件或 IM 有 API 就用 API，没有才退回 GUI。走 GUI 时要避开 Anthropic 文档列出的坑：模型有时不检查结果就当成功，下拉框和滚动条难用鼠标操作，截图缩放失真或 4K 缩小会点偏；桌面任务建议 1024×768 或 1280×720，**超出上限的截图直接被拒、不会自动缩放**【已核实】([Claude computer use 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool.md))。Mac Retina 原生截图（2880×1800）超过 Claude 高分辨率档长边 2,576 像素的上限，必须先在本地缩放，PeerDesk 现成的缩放编码管线可以复用（推断）。

## 三、模型和成本：找文件走工具约 2 美分一次，走截图贵 10–30 倍

**结论**：截图是 GUI 路线的主要成本。按 2026-11 官方价，一张 1080p 截图从 Haiku 5.5 的约 $0.0003 到 Fable 5.2 的约 $0.02；实测 OSWorld 短任务每题 $0.01–0.71，长任务 $2.9–10；同类简单文件任务走结构化工具约 $0.001–0.02，便宜 1–2 个数量级（推断）。托管模式下 GUI 任务的成本订阅费盖不住，必须工具优先并按量计费。本地小模型 2026 年已接近人类基线，但在普通笔记本上每步要十几秒，适合不看图的工具路线和隐私兜底。

各家截图计价规则都写在官方文档里【已核实】。Claude 每 28×28 像素一个 token，4.7 及以后是高分辨率档，1920×1080 不缩放记 2,691 token（标准档缩到 1456×819 记 1,560），4K 缩到上限 4,784 token ([Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision.md))；GPT-5.6-sol 的 high 档同图记 2,448 token ([OpenAI vision](https://developers.openai.com/api/docs/guides/images-vision))；Gemini 3/4 按档固定计价，默认 high 1,120，ultra_high 2,240，文档说 computer use 等场景需要 ultra_high ([Gemini](https://aistudio.google.com/docs/media-resolution))；Qwen3-VL 每 32×32 像素一个 token ([阿里云](https://www.alibabacloud.com/help/en/model-studio/vision))，第三方算 1080p 约 2,025 token ([Jacar](https://jacar.es/?p=5454))。此外，Claude 的 computer use 工具集每次请求光工具定义就约 4,500 输入 token，而 bash 工具只要 325 token【已核实】([Claude 价格](https://platform.claude.com/docs/en/about-claude/pricing.md))。下表按官方价折算单张截图的输入费用（推断）：

实测每任务费用只有一篇论文。cua-speedrun 在 OSWorld 50 题上测得 Claude Opus 5 high **$0.661/题**、low $0.390，Sonnet 5 high $0.309，GPT-6 Astra low $0.71，Gemini 3.8 Flash low **$0.11**（分数 91.6，是本次看到性价比最高的云端 GUI 模型），GPT-5.6 Luna low 约 $0.01（分数只有 61.8）；长任务 OSWorld2 上 Opus 5 low **$10.0/题**、Sonnet 5 low $8.86、GPT-6 Astra high $7.39、Gemini 3.8 Flash medium $2.91【已核实】([cua-speedrun](https://arxiv.org/html/2609.40284))。这些数字不含环境托管，分数是部分得分口径，也没有 Claude 5.5 代的实测。对照之下，工具路线的简单文件任务按 3 轮调用、每轮约 3,000 输入 token 加 200 输出 token 估算，Sonnet 5.5 约 **$0.024**、Haiku 5.5 约 **$0.0012**（推断）。真实用户的量级可参考一个案例：Tailscale 博客作者用 Claude Sonnet 4.6 跑 OpenClaw，Token 费约 $7/天【已核实，单个案例】([Tailscale](https://tailscale.com/blog/openclaw-tailscale-aperture-serve))。托管模式的账很清楚（推断）：一个付费用户每天 20 个简单任务，全走工具约 $0.5/天、$15/月，全走 GUI 约 $6–14/天，任何订阅价都盖不住后者，所以托管云必须工具优先、按任务计量。缓存能省一部分：Opus 5.5 和 Sonnet 5.5 的缓存读取是基础价的 0.05 倍，但 Anthropic 建议成批而不是每轮裁剪旧截图，否则前缀变动会让缓存失效【已核实】([Claude computer use 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool.md))。

本地模型 2026 年进步很大，但还扛不起 GUI 路线。微软 Mage-VL-Cowork（4B，Apache-2.0）在 OSWorld-Verified 上两次运行得 65.33% 和 66.75%（50 步上限，只保留最近 3 张截图），bf16 权重 9.48 GB；同一模型卡列出 ScaleCUA-Qwen3.5-9B 68.7%、GPT-5.5 78.7%、人类 72.4%【已核实，自报】([Mage-VL-Cowork](https://huggingface.co/microsoft/Mage-VL-Cowork))。速度是硬伤：社区在 M1 Pro 16 GB 上测 Qwen3-VL-8B 4-bit，预填充 157.8 token/秒、生成 31.6 token/秒、首 token 6.5 秒【已核实，社区数据】([oMLX](https://omlx.ai/benchmarks/q6m7miny))。据此推算，一张 1080p 截图光预填充就要约 13 秒、每步约 16 秒，截图缩到 720p 约 9 秒，比云端前沿模型的 6–7 秒慢 1.3–2.7 倍，成功率还低 12–20 个百分点（推断）。cua-speedrun 评测的开放权重模型也没有一个落在“性能–时间”或“性能–成本”的帕累托前沿上【已核实】([cua-speedrun](https://arxiv.org/html/2609.40284))。本地模型真正好用的地方是工具路线：选工具、读文本不需要看图，4B 级文本模型就够，“离线也能找文件”可以兑现（推断）。PeerDesk 是 Rust 单二进制，内嵌推理会显著增大体积和平台适配面，更务实的做法是可选连接本机 Ollama、LM Studio 这类 OpenAI 兼容端点（推断）。

同类产品普遍是“托管订阅为主、有限 BYOK”，而且 BYOK 的隐私承诺常常打折。Raycast 的 BYOK 只给 Pro，Anthropic、Google、OpenAI 三家的请求仍经 Raycast 服务器中转【已核实】([Raycast](https://manual.raycast.com/ai/bring-your-own-key))；Cursor 的零数据保留政策不适用于自带 Key 的请求【未核实】([Cursor 论坛](https://forum.cursor.com/t/when-will-cursor-fully-support-byok/164375))。新变化是订阅开始附带 API 额度，让“用自己订阅的额度”变得现实：Claude Max $100/月含每月 $100 API 额度，Ultra $200/月含 $200【已核实】([Claude Pricing](https://claude.com/pricing))，ChatGPT Business 含每月最多 $500 API 额度【已核实】([OpenAI](https://openai.com/api/pricing/))。托管的 Agent 运行环境也开始单独计价：Claude Managed Agents 在 token 之外按会话运行时 $0.08/小时收费，computer use 工具集不在其中提供【已核实】([Claude 价格](https://platform.claude.com/docs/en/about-claude/pricing.md))。建议的组织方式（推断）：开源版默认 BYOK，Key 留在被控端、直连模型厂商，不经 PeerDesk 服务器（不学 Raycast 中转，否则削弱“Key 不出本机”的卖点），另可选本机 OpenAI 兼容端点；托管云作为付费项提供模型路由（简单任务用便宜模型）和统一计量，计费挂在账户上；BYOK 额度用完或本地模型能力不够时，明确告诉用户原因和办法，不悄悄切到托管模型。

## 四、安全和权限：提示注入挡不住，只能靠隔离、分级和确认锁住损失

**结论**：屏幕和网页里的文字劫持 Agent 已在真实产品上反复得手。厂商的分层防护把单次攻击成功率从 20%–60% 压到 0.5%–3%，但都承认问题没有解决，而 PeerDesk 通过 API 调模型拿不到厂商产品里的全套防护。所以必须假设 Agent 迟早会被劫持一次，用隔离、权限分级、手机确认和审计把那一次的损失锁在可撤销的范围内。MCP 和“本机 Agent 加远程访问”还带来远控厂商熟悉的另一类风险：服务暴露在公网、认证被绕过、技能市场投毒，OpenClaw 是最近的反面教材。

事故时间线（原笔记多标为二手，这里一律记【未核实】）：2024-10，研究者做了一个只写着“下载并运行 Support Tool”的网页，Claude Computer Use 测试版照做，自己执行 `chmod +x`，机器随后连上攻击者的 C2 服务器 ([Embrace The Red](https://embracethered.com/blog/posts/2024/claude-computer-use-c2-the-zombais-are-coming))；2025-08，Brave 披露 Perplexity Comet 被 Reddit 评论里藏的指令驱使，读取用户邮箱和一次性验证码并发出 ([Brave](https://brave.com/blog/comet-prompt-injection/))；2025-10，Brave 又演示在截图里用人眼几乎看不见的淡色文字藏指令 ([Brave](https://brave.com/blog/unseeable-prompt-injections/))，这一条和 PeerDesk 直接相关，因为 PeerDesk 的 Agent 读的就是截图；2026-03 OECD 事故库收录 Comet 被一封恶意日历邀请零点击劫持，外泄本地文件和 1Password 凭据 ([OECD](https://oecd.ai/en/incidents/2026-03-03-3fd7))。NIST CAISI 联合多方办的红队竞赛有 400 多人、超过 25 万次攻击，**每个被测前沿模型都至少被攻破一次** ([NIST](https://www.nist.gov/blogs/caisi-research-blog/insights-ai-agent-security-large-scale-red-teaming-competition))。厂商公开的攻击成功率测法各不相同，不能横向比较，下表连同测法列出：

MCP 带来三类特有风险，事例均【未核实】。第一，工具描述是“模型看得见、用户看不见”的指令通道：Invariant Labs 2025-04 演示恶意服务器借合法的 whatsapp-mcp 外泄聊天记录，并提出“换钩子”（用户批准后服务器再改描述）([Invariant](https://invariantlabs.ai/blog/whatsapp-mcp-exploited))；Cursor 的 MCPoison（CVE-2025-54136）是批准过的配置被悄悄替换；2025-09 的 postmark-mcp 先发 15 个干净版本，第 16 版开始把所有邮件密送攻击者，是第一个确认在野外出现的恶意 MCP 服务器 ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mcp-security-crisis-20260504/))。第二，本地服务器等于以用户身份执行任意命令：mcp-remote 的 CVE-2025-6514（CVSS 9.6）让恶意远程服务器在客户端机器上执行命令 ([JFrog](https://jfrog.com/blog/2025-6514-critical-mcp-remote-rce-vulnerability/))；MCP Inspector 的 CVE-2025-49596 分数各处写 9.4 或 9.8，以 NVD 为准 ([NVD](https://nvd.nist.gov/vuln/detail/CVE-2025-49596))；OX Security 2026-04 称官方 SDK 的 stdio 设计存在命令注入根因，波及约 20 万实例（OX 自估）([OX](https://www.ox.security/blog/mcp-supply-chain-advisory-rce-vulnerabilities-across-the-ai-ecosystem))。第三，大量服务无认证暴露在公网：Censys 2026-04-28 发现 12,520 个公网可访问的 MCP 服务，2026-05-06 超过 2.1 万 ([Censys](https://censys.com/blog/mcp-servers-on-the-internet/))。和 PeerDesk 最像的反面教材是 OpenClaw：2026-01 至 02，Bitsight 13 天内观测到超过 3 万个暴露实例，SecurityScorecard 称 15,200 个可被远程执行代码；其中一个漏洞是经 Nginx 或 Caddy 反向代理后所有连接都像来自 localhost，认证被整个绕过；技能市场 ClawHub 的恶意技能数，各家统计从 386 个、约 900 个（约占 20%）到 1,184 个不等，一项学术审计在 2,556 个技能里只标出 49 个，口径差异极大 ([The Register](https://www.theregister.com/2026/02/03/openclaw_security_problems/))、([The Register](https://www.theregister.com/2026/02/05/openclaw_skills_marketplace_leaky_security/))。中国工信部 2026-02-05 发布 OpenClaw 安全提示，2026-03 银行、国企、政府机关被通知不得在办公设备上安装（严格程度各报道说法不一）([Bloomberg](https://www.bloomberg.com/news/articles/2026-03-11/china-moves-to-limit-use-of-openclaw-ai-at-banks-government-agencies))。

规范已经给出做法【已核实】([MCP 授权规范](https://modelcontextprotocol.io/specification/latest/basic/authorization))、([MCP 安全最佳实践](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices))。授权整体仍是可选项，stdio 传输不用这套授权、从本地环境拿凭据；HTTP 传输若做授权，必须 OAuth 2.1 加 PKCE，服务器必须实现受保护资源元数据（RFC 9728），客户端必须带资源指示（RFC 8707）并校验签发方 `iss`（RFC 9207），客户端注册推荐 CIMD、DCR 已弃用，服务器“MUST NOT accept or transit any other tokens”，即禁止令牌透传；客户端一键安装本地服务器时必须完整显示要执行的命令并要求明确批准，应高亮 `sudo`、`rm -rf` 等危险模式；授权网址必须拒绝 `javascript:`、`file:` 等协议，不得用 shell 打开（CVE-2025-6514 就栽在这里）。落到 PeerDesk（推断）：本地 MCP 只走 stdio 或仅本机用户可访问的 Unix 套接字、命名管道，远程只走 PeerDesk 自己已认证的 QUIC 通道，绝不监听 0.0.0.0，也不把“来自 localhost”当作可信；工具描述固定在二进制里、随版本签名，不从网络动态拉取，从根上避免换钩子；以后开放第三方技能时按代码对待：签名、审核、沙箱，定义一变就重新征求同意。

远控工具被诈骗利用是老问题，Agent 会把它放大。FBI IC3 2025 年报统计美国技术支持诈骗损失约 21 亿美元、投诉 47,794 起【未核实】([The Register](https://www.theregister.com/2026/04/07/cybercrime_losses_reach_alltime_high/))；微软 2024-05 披露 Storm-1811 冒充技术支持、经 Quick Assist 进入电脑后投放 Black Basta 勒索软件，应对是加警告，并建议只在自己主动联系支持时才放行【未核实】([Microsoft](https://microsoft.com/en-us/security/blog/2024/05/15/threat-actors-misusing-quick-assist-in-social-engineering-attacks-leading-to-ransomware))；Android 2025-12 在美国扩大试点，用户与陌生号码通话又在屏幕共享时打开金融应用，就弹出红色“立即挂断”和 30 秒等待【未核实】([Google](https://blog.google/security/android-expands-pilot-in-call-scam-protection-financial-apps/))；国家金融监督管理总局 2024-07 已把“共享屏幕”列为新型电信网络诈骗【未核实】([新华网](https://www.news.cn/legal/20251210/47903beb12a84147ae9252fecbedb957/c.html))。平台也把“AI 模拟用户操作”当风险：2025-12 豆包手机助手用系统级权限操作 App，被微信强制下线，淘宝、支付宝、京东也加以限制，豆包随后主动收缩金融等场景【未核实】([澎湃](https://www.thepaper.cn/newsDetail_forward_32094236))。加了 Agent 以后（推断），骗子不必亲手远控，诱导受害人把 Agent “绑定”给自己的聊天账号，或让受害人自己下指令即可，屏幕上没有陌生鼠标在动；聊天账号或手机被盗就等于电脑被控；Agent 去操作微信、支付宝、网银，还可能让用户账号被风控封禁。

业内标准做法已经收敛。隔离：Windows Agent Workspace 给每个 Agent 独立账户和独立会话，动作可与用户区分并写入防篡改审计日志【已核实】([Microsoft Support](https://support.microsoft.com/en-us/windows/ai/ai-features/experimental-agentic-features))；Anthropic 建议用专用的最小权限虚拟机或容器、不给登录凭据、网络走白名单【已核实】([Claude computer use 文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool.md))。最小权限：Windows 已知文件夹三档授权，Claude in Chrome 按站点授权、默认屏蔽金融服务网站【已核实】([Claude in Chrome](https://claude.com/blog/claude-for-chrome))。确认和接管：Operator 在风险操作前主动请求确认的召回率 92%，银行交易一律拒绝，敏感网站上用户离开就暂停，登录和付款由用户亲自输入【已核实】([Operator 系统卡](https://openai.com/index/operator-system-card))；Google 另加一个只看动作元数据、不看网页原文的独立模型逐个审查动作【未核实】([Google](https://blog.google/security/architecting-security-for-agentic/))。设计原则上，Meta 的“Agent 二选一规则”（2025-10-31）要求一个会话最多同时具备“处理不可信输入、访问敏感数据、改变状态或对外通信”中的两项，三项都需要时必须有人批准【未核实】([Meta](https://ai.meta.com/blog/practical-ai-agent-security/))；CISA 等五眼机构 2026-04/05 的联合指南强调“系统提示是指令，不是控制手段”【未核实】([CISA](https://content.govdelivery.com/accounts/USDHSCISA/bulletins/41544ff))。远控同行也一样：TeamViewer、GoTo、Kaseya、NinjaOne、向日葵都把“人工批准加审计日志”做成默认（见第一节），PeerDesk 不做这一层会显得不专业。综合这些做法，PeerDesk 的权限可以分四级（推断）：

| 层级 | Agent 能做什么 | 确认方式 | 业内参照 |
|---|---|---|---|
| 0 只读 | 搜文件、读文件文本、看截图并回答 | 首次授权 | Windows 已知文件夹“每次询问”；《实施意见》“智能体自主决策” |
| 1 可撤销操作 | 打开文件和应用、在白名单应用里点击输入、把文件发回本人设备 | 按应用授权“始终、本次、从不” | Windows Agent Workspace 三档；Claude in Chrome 按站点授权 |
| 2 有后果 | 发给他人、删除或移动文件、执行命令、装软件、提交表单 | 每次在手机上确认，预览具体动作和目标 | Operator 和 Claude 的确认；MCP“完整显示命令”；《实施意见》“需用户授权决策” |
| 3 默认禁止 | 网银、支付、证券、钱包、密码管理器、系统安全设置 | 默认关闭；只能在被控端本地开启，并有冷静期 | Claude in Chrome 屏蔽金融站点；Operator 拒绝银行交易；Android 30 秒等待；《实施意见》“仅限用户本人决策” |

配套措施（推断）：新增可下指令的设备要在被控端本地确认并设冷静期（参照 Quick Assist“只放行自己发起的支持”）；被控端始终显示“Agent 正在操作”标识，本地任何真实键鼠输入立即暂停 Agent，手机和被控端都有一键急停；限制每分钟动作数和每小时高危动作数，防被劫持后批量破坏；审计日志记录时间、发起人、来源设备、模型给出的理由、动作前后截图哈希和确认人，用哈希链防篡改，可选会话录像（PeerDesk 已有编码管线，成本很低）；落实“二选一规则”，Agent 处理网页、邮件这类不可信内容时只读不外发，要外发就由人确认。

法规上（不构成法律意见）：中国《智能体规范应用与创新发展实施意见》（2026-05-08，网信办、发改委、工信部）要求厘清“仅限用户本人决策、需用户授权决策、智能体自主决策”三类边界，“智能体执行操作不得超出用户授权范围”，日常办公属低风险领域，以合规自测和信息报告为主【未核实，新华网报道，未拿到原文】([新华网](https://www.news.cn/politics/20260508/aa31c404610e4cc59f47fea3ab04929b/c.html))，正好对应上表的第 3、2、0–1 级。把截图发给云端模型更直接地受《个人信息保护法》约束：截图里常有第三方个人信息和金融账户这类敏感个人信息，处理敏感信息要单独同意（第二十九条）并做影响评估（第五十五条），发给境外模型构成出境，要满足第三十八、三十九条【已核实】([个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm))；《生成式人工智能服务管理暂行办法》只适用于向境内公众提供的服务（第二条）【已核实】([网信办](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm))，托管云若向中国公众提供 Agent 服务很可能落入范围，纯 BYOK 工具形态适用性较弱，要请律师确认（推断）。产品上应提供境内或本地模型可选、发送前本地打码（账号、证件号、银行卡号）、“不保存截图、不用于训练”的承诺和开关（推断）。威胁建模可直接套用 OWASP 代理应用十大风险（2026 版，2025-12-09 发布）：ASI01 目标劫持对应屏幕注入，ASI02 和 ASI05 对应 shell 和文件操作，ASI04 对应 MCP 工具和技能，ASI09 对应被骗点确认和诈骗，ASI10 对应急停【发布日期已核实，条目未核实】([OWASP](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications/))。欧盟《AI 法案》的高风险义务已被推迟到 2027-12-02 和 2028-08-02【未核实】([Orrick](https://www.orrick.com/ja-JP/Insights/2026/07/EU-AI-Act-Update-Digital-Omnibus-Finalizes-8-Compliance-Changes))，通用远程桌面 Agent 一般不在高风险清单内（推断）。

## 六、对 PeerDesk：胜负手是常驻、穿透、实时接管和审计，MVP 从“找文件、发文件”起步

**结论**：护城河不在 Agent，而在“让任意模型或 Agent 可靠、安全地触达任意一台常驻电脑，并且人随时能看、能接管”。这一层大厂各自只服务自家生态，国内远控同行闭源且绑账号，OpenClaw 没有安全的远程通道。PeerDesk 的设备码、无人值守服务、NAT 穿透和中继、低延迟画面正好是 Agent 的“手和眼”需要的通道，再加上权限和审计这道“闸门”。

| 竞品 | 已查到的短板 | PeerDesk 对应的能力 |
|---|---|---|
| Claude Dispatch | 电脑必须醒着且 App 开着；不接新用户；不能多线程；只连 Claude【已核实】 | 无人值守服务、开机自启、多设备、模型中立 |
| ChatGPT Work / Codex | 手机发起的任务是否在自己电脑上执行没说清；computer use 首发只支持 macOS【已核实】 | Windows、macOS、Linux 被控端 |
| 腾讯 WorkBuddy | 一台电脑只允许一部手机，报道只提 macOS，限腾讯生态【未核实】 | 多设备、跨平台、可自托管 |
| ToDesk AI、向日葵 | 闭源、绑账号；ToDesk 执行位置不透明；向日葵 MCP 价格未公开【已核实/已读二手】 | 开源可审计、可自托管、BYOK 直连 |
| OpenClaw | 远程访问靠用户自拼，2–3 万实例暴露；没有实时画面【未核实】 | 内建已认证的 P2P/中继通道，低延迟画面和接管 |
| TeamViewer | MCP 只开放管理面，会话内能力不开放；面向企业 IT【已核实】 | 面向个人和小团队，会话内工具在权限约束下对 MCP 开放 |

架构建议（推断）：被控端的 `peerdesk` 进程同时是设备 Agent 和本地 MCP 服务，提供一小组结构化工具（文件检索、读文本、发文件、打开应用、系统状态），以后再加屏幕和键鼠。“大脑”默认是被控端直连的云端模型，各家 computer use 都是客户端工具，天然适配；这样截图和 token 流量不经过 PeerDesk 中继，中继只传聊天、审批和用户打开旁观时的视频，**Agent 会话的服务成本比纯远控还低**，贵的只有人接管时的画面。手机和电脑客户端经现有信令和 P2P/中继到达被控端；外部 Agent（Claude Desktop、Codex、OpenClaw）通过本机 `peerdesk mcp`（stdio）接入，再经 PeerDesk 通道调用远端设备的工具。长任务用 MCP 2026-07-28 的 tasks 扩展承载，不依赖长连接。GUI 操作放进独立虚拟显示或独立会话，参照 Windows Agent Workspace 和 Gemini 的隔离窗口，不抢用户鼠标，用户通过 PeerDesk 画面旁观、一键接管。按项目“诚实、不静默降级”的原则，没有屏幕录制或辅助功能权限时要明确告诉用户，而不是假装能做。建议的第一步如下（推断）：

| 项目 | 建议 |
|---|---|
| 场景 | 在手机或电脑上和“我的某台电脑”聊天：按时间、类型、位置找文件，读文件摘要，把文件发回本人设备；做不到的事说明原因，并一键打开实时画面由人接管 |
| 范围 | 只对本人账户下的设备开放；新增可下指令的设备要在被控端本地确认，并设冷静期 |
| 工具 | 不超过 8 个，描述简短：`search_files`（Windows Search / Spotlight / 目录遍历）、`read_text`（含 PDF 前几页）、`send_file` 和 `list_dir`（复用现有的 QUIC 文件传输 `crates/net/src/files.rs` 和远程浏览 `crates/net/src/browse.rs`）、`open`、`system_status` 等；第一版不做 GUI 自动操作 |
| 接口 | 同一套工具以 MCP 服务（`peerdesk mcp`，本机 stdio，远程只走已认证的 QUIC 通道）和 CLI 开放，全部在 `peerdesk` 一个二进制里 |
| 模型 | BYOK（Anthropic、OpenAI、Gemini）加本机 OpenAI 兼容端点，Key 留在被控端直连；工具路线只需文本，便宜模型和本地小模型就够 |
| 安全 | 第 0、1 级自动；第 2 级（发给他人、删除移动、执行命令）在手机上逐次确认并预览具体目标；第 3 级默认关闭；被控端常驻“Agent 正在操作”标识和急停；哈希链审计日志；限速 |
| 端到端门槛 | 自建贴近真实的任务集（真实目录结构和文件名），量任务成功率、出结果的中位时间、每任务 token 和费用、注入攻击成功率（在文件里埋带指令的文本）、每任务确认次数、每任务中继字节；测试在虚拟显示里跑，不动开发者的键鼠 |
| 收费 | 开源版免费加 BYOK；托管云卖连接层（中继、常驻、多设备、审计），对标每月 $5–12；托管模型积分按量计费，挂在账户上 |

为什么从这里起步：一是 TeamViewer 的数据表明，零门槛的功能比要人学的 Agent 普及得快两个数量级，“在手机上问一句就拿到文件”几乎不用学；二是同行都把它当招牌场景，华为的“跨端找文件”、ToDesk 宣传的“让异地办公室电脑把报表发给老板”【未核实】([凤凰网](https://tech.ifeng.com/c/8tbcCD2OFyY))；三是工具路线比 GUI 便宜 10–30 倍、快一个数量级以上、注入面更小，开源版 BYOK 用户也负担得起；四是它只用到 PeerDesk 已有的文件传输、P2P 和设备身份，而 MCP 服务已是同行标配（向日葵、TeamViewer），不做反而落后（推断）。第二阶段再加 GUI 操作：跑在独立虚拟显示里，截图缩到 720p 左右，复用现有编码管线做操作录像，并做多设备编排（参考 UFO³ Galaxy）、团队审计和 Windows 设备 MCP 注册表接入（推断）。

主要风险按严重程度排（推断）。第一是捆绑：腾讯已经把远控免费放进 Agent App，OpenAI 和 Anthropic 只差“真正的远程画面”，PeerDesk 的连接层随时可能被对手补上，所以要尽快把“模型中立、跨平台、可自托管”做成用户能感知的差异。第二是安全事故和监管：OpenClaw 的先例说明，一次大规模暴露就可能让“远控加 AI”整类产品被企业和监管一刀切，开源可审计、默认不暴露公网、每步可审计是必要防线；远控工具本来就常被骗子利用，杀毒和反诈系统的误伤还会伤到签名和信誉，所以从第一天起就要留好审计日志、举报入口和连接来源记录。第三是平台封杀：Agent 碰微信、支付宝、网银可能让用户账号被风控，所以第 3 级默认关闭，并如实告诉用户原因。第四是能力天花板：长任务严格成功率约 20%，文案和计费都不能承诺“全自动”。第五是窗口期：RustDesk 维护者已对控制端 MCP 说“Go ahead”，QuickDesk 已内置 MCP，开源远控加 MCP 很可能一年内出现。第六是合规：截图发给境外模型涉及个人信息出境，托管云面向中国公众时可能落入生成式 AI 办法的范围。此外，Windows 的设备 MCP 注册表和 MXC 一旦正式上线，企业环境可能要求第三方 Agent 走系统的注册、隔离和审计路线，签名和打包要求需要提前调研。

## 结论

这次调研最大的认识变化是：Agent 本身正在变成大模型订阅和操作系统里的免费功能，“可信地到达一台常驻电脑”反而成了稀缺品。Dispatch 要求电脑醒着，WorkBuddy 只允许一部手机，OpenClaw 用户自己拼 Tailscale 并大面积暴露，连大厂也没解决这一层。PeerDesk 的位置因此从“远控工具加 AI 功能”变成“AI 时代的连接和信任层”，既可以卖给终端用户，也可以作为 MCP 端点和安全通道卖给其他 Agent。一个反直觉的好处是，Agent 会话若由被控端直连模型，中继只传文字和审批，服务成本比视频远控还低，P2P 打洞的价值转移到了人接管时那几分钟画面上。

第二个认识是：这个领域没有任何一家公开远程 Agent 的端到端指标（任务成功率、每步延迟、流量、注入攻击成功率），基准分数又被厂商口径搅乱。PeerDesk 已有“用指标说话、门槛只升不降”的工程习惯，把这几项做进端到端测试并公开口径，本身就是差异化，也是回应“agent washing”质疑最有力的方式。动手前最值得补的信息有四项：实测 ToDesk AI 到底在哪里执行，查清向日葵 MCP 的价格，到仓库核对 Open Interpreter 等候选借用项目的许可证（AGPL 不能用），确认 Windows Agent Workspace 和 MXC 对第三方的要求以及托管云在中国的合规边界。
