# 用户实测：拖到另一块屏幕再全屏时卡几秒（2026-11-27，Mac 被控 Wi-Fi，Windows 控制）

版本 dev `7a7e3be`。日志已用 `scripts/anonymize-log.py` 脱敏；`per-second.csv`、`decisions.csv` 由 `scripts/log-to-trace.py` 从被控端日志生成（格式见 `../2026-11-27-mac-host-wifi/README.md`）。
日志里的时间是 UTC，产品负责人说的是北京时间（UTC+8）。

## 产品负责人的感受（北京时间）

1. 10:40：控制端窗口拖到另一块屏幕，然后全屏，卡了几秒（要查）
2. 10:42：稍微卡了一下，大约 1 秒，然后好了

## 数据里看到的（10:40 = 02:40 UTC）

- 控制端显示区域连变 4 次（02:39:59–02:40:10）：1944×1170 → 1296×780 → 2048×1152 → 1296×780 → 2048×1081。
  被控端一直按 2880×1800 原尺寸编码，没有换尺寸重编。
- 控制端每秒都收到、解码 20–29 帧，帧之间最长间隔基本在 110 ms 以内（全屏那一刻 227 ms）：**网络和解码没断**。
- 控制端解码每帧平均 35–60 ms（硬件解码 DXVA，但解码后拷回内存、CPU 转 RGB），2880×1800 下帧率上不去。
- 全屏后约 7 秒（02:40:09–02:40:16）被控端码率在 21 Mbps 和 0.13 Mbps 之间来回跳，帧率降到 20–30，
  大帧（90–160 KB）重传多（每秒最多 358 片）。根子同上一份日志：跟踪状态下没用满码率时按送达速率降码率。
- **控制端日志没有“画面画到屏幕上”的时间**，拖窗口和全屏时界面是不是停住了，从日志看不出来。
  推测：Windows 拖动窗口时系统接管消息循环，界面不重画；换屏幕（DPI、刷新率不同）和全屏要重建绘图表面。
