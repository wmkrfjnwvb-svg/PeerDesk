### 2.1 S1 连入确认的设计（2026-11-28 定）

- **什么时候问**：被控端设置“有人连接时要我确认”，**默认关**。核心用户连的是自己的机器，旁边没人点；
  帮别人远程（对方坐在电脑前）时打开。同账户免密（O-phase1-plan 1.1）和信任列表里的设备不问。
- **在哪一步问**：握手完成（密码对了、`Accept` 发出）之后、开始发画面之前。被控端先发一条控制消息“等对方确认”，
  控制端显示“等待对方接受……”；老版本控制端不认这条消息，只是多看一会儿黑屏，不会因此超时断开
  （握手已经完成，连接本身有保活）。
- **能力位**：新加 `Caps::CONFIRM`，控制端声明自己会显示“等待确认”；被控端照常问，只是老控制端看不到提示。
- **结果**：接受就开始发画面；拒绝或 30 秒没人理，带原因关闭连接（“对方拒绝了连接”“对方没有回应”），
  控制端照现有的拒绝原因显示，不重连。
- **被控端界面**：弹一个窗口，写清是谁（电脑名、系统、是否在账户里）、要做什么（控制、看、传文件），
  “接受 / 拒绝”加倒计时；会话中一直显示“XX 正在控制”和断开按钮（已有）。
- **测试**：集成测试三条（接受后出画面、拒绝时控制端收到原因、超时同样）；设置关着不问；老控制端（不声明能力）也能被接受。

## 3. 批 3：Agent 功能（追 Jump Desktop）

Jump 首页（2026-11-28 读）：Agent 可以用屏幕、鼠标、键盘；有 Mission Control 实时监控；任何账户免费，最多 8 台。我们的差异：Windows、Linux 同样一流，开源可自托管，传输指标公开，审批推送。

| # | 功能 | 验收 | 依赖 |
|---|---|---|---|
| G1 | **本机 MCP（只读）**：设备列表、在线、健康 | O-phase1-plan P9 | P3、P4 |
| G2 | **MCP 操作工具**：截图、点击、输入文字、按键、滚动；按风险分层（只读、可撤销、有后果），有后果的要人在手机或桌面上批准；所有操作在被控端执行并检查来源和权限 | 每个工具的协议测试；风险层的拦截测试（没批准的“有后果”操作 0 次执行）；用真的 Claude Code 跑一遍“打开某个应用、截图确认” | G1、S1 |
| G3 | **监控面板**：多台设备的实时缩略图和 Agent 在做什么（最近的操作、等批准的事项），点进去接管 | 10 台设备同时显示时缩略图的流量和 CPU 记基线；接管从点击到出画面的时间进指标 | 批 2 的设备表、S2 |
| G4 | **审计日志**：谁（人或哪个 Agent）在什么时候连了哪台、做了什么 | 每次连接、每次 MCP 操作一行；不能被控制端改写 | G2 |

G2 开工前先读 Jump 的 Agent 文档和 MCP 规范里关于计算机操作的部分，写进 `industry-*.md`，再定接口。

## 5. 先要调研的（派 Sonnet，只写文档）

1. **隐私屏和锁定键鼠**：Windows（放大镜接口的黑屏、`BlockInput`、IddCx 虚拟屏切换）、macOS（系统允许到哪一步、同行怎么做）、Linux（X11、Wayland）。读官方文档和开源实现（RustDesk 的隐私模式），写清每种做法的权限要求和限制。
